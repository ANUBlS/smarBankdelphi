Commit timing: the SB_CASHREPORT procedures commit inside the package body (Script/sb_cashreport.sql), and Delphi does not commit after them, so the API calls them with `commit=False`. transaction_commit is followed by an explicit commit, as in Delphi. Photo writes commit because CommitOnPost is set on the dataset.

## Unverified (needs the production DB or the user)

1. The bodies of `get_cash_transactions`, `get_cash_transactions_excel` and `pkg_report.get_cashinfo` are not in the repo. The mock follows the column list the grid and the dfm expect, and the get_cashinfo mock follows the commented-out SELECT in CashDataModule.dfm.
2. The repo has no `update_cashsettings` with **19** parameters: Script/sb_cashreport.sql has 15. Delphi passes 4 more (controller, controller_out, OperatorTitle, AccountantTitle), and the `cash_settings` DDL script lacks the CONTROLLER, CONTROLLER_OUT, OPERATORTITLE and ACCOUNTANTTITLE columns. The column names used for those 4 are assumed.
3. `ChooseCashSymbol` updates `provarch` only (script body), even when the grid shows 'Planlaşdırılmış' (lazytransaction). Kept as written.
4. Whether the jpeg unit is linked into CashDesk.bpl (if it is, .jpg would load but still not be stored, because DBImage stores only a bitmap). The web assumes BMP-only.
5. The decimal separator Locate uses on float fields (web uses `,`, the FloatToStr default on the bank PCs).
6. Whether DOA `Refresh` keeps the current row (web re-selects by ID).
7. The exact meaning of the `d1` column in the cursor (web follows `TransCommitClick`: commit only when NULL).
8. The SBCONFIG tree position for the new Cash symbols entry (mock only).
