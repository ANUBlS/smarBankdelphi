| Procedure | Commits inside? | Delphi commits after? | Web |

## Unverified items

1. **DBF templates** `EXCH122.dbf` and `$MB12212.dbf` are not in the repo (they sit in the Delphi client folder). The web copies whatever template is in `DBF_TEMPLATE_DIR`, so the real structure is kept, but the mock templates in `api/fixtures/dbf` have **assumed** field types and widths. Put the real files in `api/templates` (or set `DBF_TEMPLATE_DIR`) before testing on Oracle.
2. DBF encoding (`DBF_ENCODING`, default cp1251) and the decimal separator used when a float goes into a character field (`DBF_DECIMAL_SEPARATOR`, default `,`) depend on the BDE language driver and the Windows regional settings of the client.
3. `TFloatField.AsInteger` for TOTAL1 / TOTAL2 is taken as Round (banker's rounding).
4. `GetForeignCurrency` compares `avalute.val_name` with `'048'`; with ISO names (AZN, USD) it always returns COffical. Kept as is.
5. TExcelExporter (FrmPrint 'Excel') layout is not in the repo; the web writes the same xlsx as CMExcel (DisplayLabel titles).
6. `SB_MTOUTVIEW.GetBankDay` body is not in the repo; the mock returns SYSDAT.TEK_DAT.
7. `exchanges.ID` is assumed to come from a trigger / sequence; excaccount is assumed unique on (exchangeID, accountID) with an FK to account (mock only).
8. `NAT_BALANCE` / `FOR_BALANCE` column types are unknown; the edit texts are sent as strings and Oracle converts them.
9. `ExchangeViewer` / `ConvertationViewer` "Title" click: on Oracle a bind variable in ORDER BY does not change the order. If the bank's DOA version substituted it as text, the order would change - not checked on a live database.
10. Nothing has run on a real Oracle database yet.
