# Remaining SmartBank modules (Delphi OCX plugins not yet ported)

Generated by `/workspace/migration/gen_remaining_md.py` from the Delphi source (every `*_TLB.pas` CoClass GUID = a CLSID the tree can open via `axinplace:{CLSID}`) and `web/modules.json`. Already ported (not listed): shell/login/tree, Accounts, Customer_Operations, TransactionManager, SB_Credit, Balance group, all Out_ modules + OutExcelImport, AZIPS, XÖHKS, Cards. On hold: Cards reports (+Möhkəməndirmə), XÖHKS prints. Excluded by the user: SWIFT (SWIFT_INTERNATIONAL).

**Which of these are really in your tree** is decided by your DB INI (`SBCONFIG` `SmartBankIni`, section `[PluginManager\Packages]`), which is not in the repo. This list is every CoClass that *could* be registered.

Easiest check: log in to the web app on your real DB (`DB_MODE=oracle`). Its tree is built from that same INI section (api/app/sb.py `load_plugins`, as PluginSrv.pas:881-900), so every node that opens "Not migrated yet" is in scope and every module below that does not appear can be dropped. The same values can be read in SQL*Plus with the calls Delphi uses (DBIniFile.pas:58-62, 147-151):

```sql
set serveroutput on
declare id number; n number;
begin
  id := sbconfig.OpenFile('SmartBankIni');
  n  := to_number(sbconfig.ReadValue('PluginManager\Packages','Count','0'));
  for i in 0 .. n-1 loop
    dbms_output.put_line(i||' '||sbconfig.ReadValue('PluginManager\Packages','Item'||i,''));
  end loop;
end;
/
```

Columns: **units** = .pas files (without *_TLB), **forms** = .dfm, **SQL** = TOracleDataSet/Query SQL blocks in the .dfm files, **lines** = Pascal lines, **built** = PE compile date of an .ocx found in the folder (blank = no real stamp; Delphi writes 1992-06-19 by default). For CLSIDs with several copies the likely production copy is picked by: real OCX compile date, then undated/unsuffixed folder name, then size. **Check the flagged ones.**

## Suggested order

Tier 1 = daily banking (front office, cash, payments, day close). Tier 2 = admin and settings. Tier 3 = niche lines of business, reports and integrations. Within a tier, groups are in the suggested order.
